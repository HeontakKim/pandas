# gemcraft — 아크 그리드 젬 가공 최적 선택 계산기

로스트아크 아크 그리드의 **젬 가공**에서, 매 턴 뜬 4개의 선택지 중 무엇을 골라야
목표 달성 확률이 가장 높은지 계산한다. 동적 계획법으로 모든 상태의 값 함수를
정확히 풀어 두므로 결과는 근사치가 아니라 최적해다.

```
python3 -m gemcraft.cli play --grade 희귀 --goal "target=4,4,0,0"
```

## 왜 DP 인가

가공은 유한 지평 마르코프 결정 과정이다.

- 상태 = (4가지 옵션 레벨, 효과 종류 적합 여부, 누적 비용 배율, 남은 시도 `n`, 남은 리롤 `r`)
- 매 턴 확률표에서 4개의 선택지가 제시되고, 하나를 고르거나 리롤한다.

```
Q(s, n, r, 선택지) = V(s', n-1, r')
V(s, n, r)         = E_hand[ max( max_{o∈hand} Q, V(s, n, r-1) ) ]
V(s, 0, r)         = objective(s)
```

리롤의 가치 `V(s, n, r-1)` 은 같은 레이어의 더 낮은 `r` 이므로 `r` 오름차순으로
풀면 고정점 반복 없이 한 번에 계산된다. 리롤을 연속으로 여러 번 쓰는 경우도 이
재귀에 그대로 포함된다. 상태 7,500개 × 레이어 189개를 numpy 로 약 4초에 푼다.

## 사용법

### `rank` — 지금 상태의 선택지 순위표

뜬 4장을 입력할 필요가 없다. **모든 선택지의 순위표**를 뽑아 주므로, 화면에 뜬
4장 중 표에서 가장 위에 있는 것을 고르면 그게 최적이다.

```bash
python3 -m gemcraft.cli rank --grade 영웅 --goal "target=4,4,0,0+total16" \
    --levels 4,3,2,1 --attempts 3 --rerolls 1
```

```
  의지력 4 · 포인트 3 · 효과1 2 · 효과2 1 | 총합 10 (전설) | 남은 시도 3 · 리롤 1
  현재 기대치:  42.52%   (의지력 효율≥4 · 질서/혼돈 포인트≥4 · 총합≥16 달성 확률)

  순위  선택지                            등장률        선택 후
  --------------------------------------------------
  1   두번째 효과 Lv. 4 증가              0.51%      96.47%
  2   첫번째 효과 Lv. 3 증가              1.99%      74.75%
  ...
  7   의지력 효율 +1 증가                13.28%      23.87% ←리롤 기준선

  다른 항목 보기(리롤) 가치:  25.40%  → 4장 중 최고가 이보다 낮으면 리롤이 이득
```

### `play` — 대화형 진행

상태를 자동으로 추적한다. 고른 선택지만 계속 입력하면 된다.
입력 별칭: `w`=의지력, `p`=포인트, `a`/`b`=첫번째/두번째 효과,
`ca`/`cb`=효과 변경, `c+`/`c-`=비용, `k`=상태 유지, `rr1`/`rr2`=리롤 획득,
`r`=리롤 사용, `q`=종료.

```bash
python3 -m gemcraft.cli play --grade 희귀 --goal "target=4,4,0,0"
```

### `sim` — 정책 시뮬레이션

DP 정책대로 끝까지 플레이했을 때의 실제 분포, 기대 골드, 등급 분포를 낸다.

```bash
python3 -m gemcraft.cli sim --grade 희귀 --goal ancient --runs 50000
```

### 목표 (`--goal`)

| 목표 | 의미 |
|---|---|
| `ancient` | 고대 젬(레벨 총합 19+) 확률 최대화 |
| `relic` | 유물 이상(총합 16+) 확률 최대화 |
| `total` | 레벨 총합 기댓값 최대화 |
| `target=W,P,E1,E2` | 각 옵션이 지정 레벨 이상일 확률 (`0`=상관없음) |
| `weighted=a,b,c,d` | 옵션 레벨 가중합 기댓값 |

`target` 뒤에 `+total19` 를 붙이면 총합 조건이, `+good` 를 붙이면 "레벨을 요구한
효과 슬롯이 원하는 효과일 것"까지 조건에 들어간다.
예: `--goal "target=4,4,3,0+good+total17"`

### 효과 종류 다루기

효과 종류는 8종 이상이지만 최적 선택에 실제로 영향을 주는 건 "지금 붙은 효과가
내가 원하는 효과인가" 뿐이다. 그래서 슬롯당 1비트로 축약하고, `효과 변경`은
확률 `--p-good` 으로 원하는 효과가 되는 전이로 모델링한다. 딜러가 8종 중 3종을
원한다면 `--p-good 0.375`. 현재 붙은 효과가 쓸모없다면 `--eff1-bad` / `--eff2-bad`.

## 규칙 출처

모든 수치는 `gemcraft/rules.py` 한 곳에 모여 있다. 패치가 나면 이 파일만 고치면 된다.

- **선택지 확률표(27종)와 미등장 조건**:
  [공식 확률 정보 공개 — 젬 가공, 젬 융합](https://m-lostark.game.onstove.com/Probability/%EC%A0%AC%20%EA%B0%80%EA%B3%B5,%20%EC%A0%AC%20%EC%9C%B5%ED%95%A9).
  확률 합계는 정확히 100.0000% 이며 테스트로 검증한다.
- **등급별 가공 시도 / 다른 항목 보기 횟수, 가공 후 등급 판정**:
  [공식 게임 가이드 — 아크 그리드](https://m-lostark.game.onstove.com/GameGuide/Pages/%EC%95%84%ED%81%AC%20%EA%B7%B8%EB%A6%AC%EB%93%9C).
  고급 5회/0리롤, 희귀 7회/1리롤, 영웅 9회/2리롤. 전설 4~15 / 유물 16~18 / 고대 19+.
  리롤은 가공을 1회 진행한 뒤부터 사용 가능.
- 가공 1회 900골드, 비용 ±100% 옵션은 남은 시도에 계속 적용 ([Maxroll](https://maxroll.gg/lost-ark/resources/ark-grid-system-guide)).

### 모델링 가정 (확정 자료를 못 찾은 부분)

**4개 선택지는 각 슬롯이 확률표에서 독립적으로 뽑힌다고 가정한다** (중복 등장 가능).
공식 표가 선택지 하나하나에 확률을 주고 합이 정확히 100% 인 점이 이 해석을 뒷받침한다.
만약 실제로는 중복 없이 4개를 뽑는다면 값 함수가 미세하게 달라지지만, 눈앞의 4장 중
무엇을 고를지는 `Q` 의 대소 관계로 정해지고 그 순서는 이 가정에 거의 영향받지 않는다.

`가공 상태 유지` 는 시도 1회를 소모하고 아무것도 바꾸지 않는 것으로,
`효과 변경` 은 레벨을 유지한 채 종류만 다시 뽑는 것으로 모델링했다.

### 외부 정합성

정책대로 끝까지 가공했을 때의 결과 (2만 회 시뮬레이션, 목표 `ancient`):

| 젬 등급 | 전설 | 유물 | 고대 | 평균 골드 | 평균 레벨 |
|---|---|---|---|---|---|
| 고급 (5회) | 96.4% | 3.2% | 0.4% | 4,495 G | 2.8 / 2.8 / 2.9 / 2.8 |
| 희귀 (7회) | 37.9% | 35.2% | 26.9% | 6,301 G | 4.0 / 4.0 / 4.1 / 4.1 |
| 영웅 (9회) | 1.5% | 8.8% | 89.6% | 8,102 G | 4.8 / 4.8 / 4.8 / 4.8 |

희귀 젬의 평균 결과가 `4.0 / 4.0` 으로 나오는 것은 커뮤니티 통설인
"희귀 젬은 의지력 효율 4 / 포인트 4 가 현실적 목표"와 정확히 일치한다.

## 알아 두면 좋은 것

계산 결과가 반직관적으로 보일 때가 있는데, 대체로 **선택지 풀 재정규화** 때문이다.
예를 들어 `의지력4·포인트3·효과1:2·효과2:1` 에서 총합 16 을 노릴 때, 모델은
`포인트 +1`(→4, 목표 조건 충족) 보다 `의지력 +1`(→5) 을 더 높게 친다.

의지력이 5가 되면 의지력 증가 옵션 4종이 통째로 미등장 처리되어 풀의 확률 질량이
83.35% → 76.10% 로 줄고, 남은 큰 점프 옵션(`포인트+2`, `효과1+3`, `효과2+4`)의
등장률이 4.74% → 10.97% 로 두 배 이상 뛴다. 죽은 선택지를 먼저 없애 좋은 선택지가
뜰 확률을 끌어올리는 것이 이득인 상황이다.

## 구조

```
gemcraft/
  rules.py       공식 확률표·상수 (패치 시 여기만 수정)
  state.py       상태 인코딩, 유효성 행렬, 전이 테이블
  objectives.py  목표 함수와 --goal 파서
  solver.py      DP 및 정책 조회
  simulate.py    정책 시뮬레이터
  cli.py         명령행 인터페이스
tests/
```
